# rabcl_esp32 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gamma_turret_fw の main.cpp にある ESP-IDF 依存コードを `CanBus` / `DebugLed` に切り出し、新リポジトリ rabcl_esp32（ESP-IDF コンポーネント）へ移して、gamma_turret_fw が submodule で使う形にする。

**Architecture:** rabcl（不変）→ rabcl_esp32（ドライバのラッパー、rabcl に依存しない）→ 各ファーム（board.hpp + main.cpp）。クラスはまず gamma_turret_fw 内で切り出して実機確認し、動いたものを rabcl_esp32 に移す。直結試験は rabcl_esp32 の example になり、gamma_turret_fw は骨組みに戻る。

**Tech Stack:** ESP-IDF 5.5.5（pioarduino 55.03.312、PlatformIO Core は pioarduino 6.2.0）、C++17、FreeRTOS、esp_driver_twai（新 API）、GitHub Actions

**Spec:** `docs/superpowers/specs/2026-10-20-rabcl-esp32-design.md`

## Global Constraints

- ESP-IDF 5.5.5 / pioarduino 55.03.312。TWAI は `esp_twai.h` / `esp_twai_onchip.h`（旧 `driver/twai.h` は使わない）
- C++17。定数は UPPER_SNAKE_CASE、クラス・関数は UpperCamelCase。名前空間は `rabcl_esp32`
- rabcl に ESP-IDF 依存のコードを入れない（CMake の分岐のみ）。rabcl_esp32 に機体固有の値を入れない（example は除く）
- コンストラクタはハードを触らない。`Start()` で初期化して `esp_err_t` を返す。ISR（`IRAM_ATTR`）ではログを出さず、キューとカウンタだけ更新する
- ビルドは PowerShell から `pio run`。同時に 2 つのビルドを走らせない
- コミットは 1 行メッセージ、ユーザーの承認後。新リポジトリは `# rabcl_esp32` 1 行の README で `initial commit`
- 実機: Stamp-P4（ESP32-P4 v1.3、COM3）+ gamma_turret_pcb v1.0。CAN 試験は 24V と CAN1 ⇔ CAN2 直結ケーブルが必要

## Review Focus

- CanBus の受信キューが溢れたとき: フレームを捨てて `rx_dropped` を数え、ISR 内で止まらない（Task 1 の example で 8 フレーム連続送信して確認）
- `Send` に 8 バイト超の dlc を渡したとき: `ESP_ERR_INVALID_ARG` を返して送信しない（Task 1 で確認）
- `Start()` を 2 回呼んだとき: 2 回目は `ESP_ERR_INVALID_STATE` を返し、ノードを二重に作らない（Task 1 で確認）
- 相手がいない（ACK 無し）状態で `Send` を続けたとき: `tx_fail` と `bus_error` が増えるだけで、ノードは error_active に戻れる。バスオフになったら `auto_recover` で復帰して `recovered` が増える（Task 1 で 24V 無しの状態を使って確認）
- rabcl の CMake 分岐が ROS 2 ビルドを壊さないこと（Task 2 で rabcl の CI を確認）

```cpp
// debug_led.hpp
struct DebugLedConfig { gpio_num_t pin; bool active_low = true; };
class DebugLed {
public:
  explicit DebugLed(const DebugLedConfig & config);
  esp_err_t Start();          // gpio_config して消灯状態にする
  void Set(bool on);
  void On(); void Off(); void Toggle();
};

// can_bus.hpp
struct CanFrame { uint32_t id = 0; uint8_t dlc = 0; uint8_t data[8] = {}; bool ext = false; bool rtr = false; uint64_t timestamp_us = 0; };
struct CanBusConfig {
  gpio_num_t tx; gpio_num_t rx; uint32_t bitrate;
  uint32_t tx_queue_depth = 8; uint32_t rx_queue_depth = 16;
  int8_t fail_retry_cnt = 3; bool auto_recover = true;
};
struct CanBusCounters { uint32_t tx_fail = 0; uint32_t bus_error = 0; uint32_t rx_dropped = 0; uint32_t bus_off = 0; uint32_t recovered = 0; };
class CanBus {
public:
  explicit CanBus(const CanBusConfig & config);
  ~CanBus();                                  // Stop() 相当 + node delete + queue delete
  esp_err_t Start();                          // 2 回目は ESP_ERR_INVALID_STATE
  esp_err_t Stop();
  esp_err_t Send(const CanFrame & frame, TickType_t timeout);  // dlc > 8 は ESP_ERR_INVALID_ARG。送信完了まで待つ（ブロッキング）
  bool Receive(CanFrame & frame, TickType_t timeout);          // キューから 1 フレーム。無ければ false
  CanBusCounters GetCounters() const;
  esp_err_t GetStatus(twai_node_status_t & status) const;
  esp_err_t Recover();                        // バスオフからの手動回復
};
```

- `board.hpp`（`namespace board`）: `DEBUG_LED2_PIN = GPIO_NUM_37`、`DEBUG_LED3_PIN = GPIO_NUM_38`、`CAN1_TX_PIN = GPIO_NUM_23`、`CAN1_RX_PIN = GPIO_NUM_21`、`CAN2_TX_PIN = GPIO_NUM_19`、`CAN2_RX_PIN = GPIO_NUM_17`、`CAN_BITRATE = 1000000`

- [ ] **Step 1: `board.hpp` と `debug_led.hpp/.cpp` を作る**。既存 main.cpp の `InitDebugLed` を `DebugLed::Start` に移す（吸い込みは `active_low = true`）
- [ ] **Step 2: `can_bus.hpp/.cpp` を作る**。既存 main.cpp の `InitCan` / `OnRxDone` / `OnTxDone` / `OnError` / `OnStateChange` / `Send` / `LogNodeStatus` をクラスに移す。受信キューはインスタンスごとに `xQueueCreate(rx_queue_depth, sizeof(CanFrame))`。`OnStateChange` で `new_sta == TWAI_ERROR_BUS_OFF` なら `bus_off++` と回復要求フラグを立てる（ISR ではドライバ API を呼ばない）。`auto_recover` のときは次の `Send` / `Receive` の呼び出し時にフラグを見て `twai_node_recover` を呼び、error_active へ戻った状態変化で `recovered++`。`xQueueSendFromISR` が失敗したら `rx_dropped++`
- [ ] **Step 3: main.cpp を書き換える**。`board::` の定数で `DebugLed led3` と `CanBus can1, can2` を作り、1 秒ごとに CAN1 → CAN2、CAN2 → CAN1 へ 1 フレーム送って `Receive` した内容をログ、10 秒ごとに `GetCounters` と `GetStatus` をログ。Review Focus 用に、起動 5 秒後に CAN1 から 8 フレーム連続送信（`rx_dropped` の確認）と、`dlc = 9` の `Send` が `ESP_ERR_INVALID_ARG` を返すことのログ、`Start()` の 2 回目が `ESP_ERR_INVALID_STATE` を返すことのログを 1 回だけ出す
- [ ] **Step 4: ビルド**。Run: `pio run -e stamp_p4`（PowerShell）。Expected: `[SUCCESS]`、main.cpp / can_bus.cpp に warning 無し
- [ ] **Step 5: 実機確認（24V 無し）**。書き込んでコンソールを読む。Expected: `tx_fail` と `bus_error` が増え、state が error_passive まで行くか、bus_off → `recovered` が増える。クラッシュしない
- [ ] **Step 6: 実機確認（24V あり、直結）**。Expected: 両方向の受信ログが毎秒出て、`GetCounters` が全部 0（8 フレーム連続送信後に `rx_dropped` が 0 か、溢れた分だけ増える）。`dlc = 9` と 2 回目 `Start()` のログが期待どおり
- [ ] **Step 7: コミット**（承認後）: `CanBus と DebugLed をクラスに切り出す`
